# Gap checklist (readiness reminder)

This is a short reminder of the gap areas worth checking when you read
the uploaded documents. It is NOT a schema, a form, or an audit
template — do not number items, score them, track coverage, or record
sources. Just use it to decide which objective questions are worth
asking the user before generation starts.

Prioritize the cover fields first; ask about the rest only when the
documents leave a real, blocking gap.

- **Cover identity (highest priority).** Is the partner clear? The
  customer? The project title? The funding type? These four render on
  the document header — if any is missing or ambiguous, ask directly.
  *e.g. "Which funding mechanism covers this engagement?"*

- **Problem and solution direction.** Do the documents state the
  business problem and the proposed solution direction in a sentence or
  two? *e.g. "In one line, what's the core problem this project solves?"*

- **Integrations and data sources.** Are the systems to integrate with,
  and the data sources involved, named? These are client-specific and
  cannot be inferred. *e.g. "Which external systems must this integrate
  with, and who owns each side?"*

- **NFR targets.** Are there quantitative quality targets (performance,
  availability, security, etc.)? Vague NFRs weaken the SOW.
  *e.g. "Any concrete targets for performance or availability?"*

- **Timeline.** Is there a start, an end, or a duration? Timelines are
  commitments and shouldn't be invented. *e.g. "Is there a target start
  date or overall duration?"*

- **Operational constraints.** Are there hard constraints — network,
  VPN, cloud org structure, security approvals, data residency,
  compliance — that shape delivery? *e.g. "Any environment or security
  constraints we must work within?"*

Do NOT ask about things a consultant can safely default and the user can
review later: technology stack choices, typical out-of-scope items,
typical team composition, engagement shape, or common compliance
defaults. Those are filled downstream and surfaced at the Content Review
gate, not here.
